# B-RAG 실험 가이드

## 📋 개요

이 가이드는 B-RAG(Balanced Retrieval-Augmented Generation) 실험을 위한 최신 방법론을 설명합니다. 실험은 `b_rag_test_notebook.ipynb` 노트북을 기준으로 진행됩니다.

## 🗂️ 프로젝트 구조

```
liberty_agent/b_rag/
├── core/                      # 핵심 기능 구현
│   ├── question_generation/   # 질문 생성 모듈
│   ├── rag_system/           # RAG 시스템 구현
│   └── schemas/              # 데이터 스키마 정의
├── experiments/              # 실험 관련 코드
│   ├── notebooks/            # 실험용 노트북
│   │   └── b_rag_test_notebook.ipynb  # 주요 실험 노트북
│   ├── configs/              # 실험 설정
│   ├── prompts/              # 프롬프트 파일
│   └── b_rag_experiment_runner.py  # 실험 실행기
├── data/                     # 데이터 저장소
└── results/                  # 실험 결과 저장
```

## 🚀 실험 프로세스

### 1. 환경 설정 및 초기화 (셀 1)

**목적**: 실험 환경을 설정하고 자동 로깅 시스템을 초기화합니다.

**주요 기능**:
- 타임스탬프 기반 세션 ID 생성
- 로그 디렉토리 생성 (`b_rag_experiment_logs/[TIMESTAMP]_session/`)
- 실험 메타데이터 초기화
- Python 경로 설정

**실행 결과**:
- 로그 디렉토리가 생성됩니다.
- 세션 메타데이터가 초기화됩니다.

### 2. 모듈 임포트 및 프롬프트 생성 (셀 2)

**목적**: 필요한 모듈을 임포트하고 프롬프트 파일을 생성합니다.

**주요 기능**:
- 들여쓰기 오류 수정 함수 실행
- 확장 난이도 프롬프트 파일 생성
- 필수 모듈 임포트 (질문 생성기, RAG 시스템, 스키마 등)
- 전역 변수 초기화

**실행 결과**:
- 프롬프트 파일이 생성됩니다.
- 필요한 모듈이 임포트됩니다.

### 3. 검증 우회 API 질문 생성 (셀 3)

**목적**: API를 직접 호출하여 질문을 생성합니다.

**주요 기능**:
- 모듈 강제 리로드
- 질문 생성기 초기화 (난이도 옵션 추가)
- API 직접 호출 (검증 우회)
- 응답 파싱 및 결과 저장

**실행 결과**:
- 생성된 질문이 전역 변수 `generated_questions`에 저장됩니다.
- GT 질문이 전역 변수 `test_gt_question`에 저장됩니다.
- 생성된 질문 목록이 출력됩니다.

### 4. 현재 생성된 질문 검증 및 로드 (셀 4)

**목적**: 현재 메모리에 있는 생성된 질문을 검증하고 로드합니다.

**주요 기능**:
- 현재 메모리의 질문 검증
- 답변 분포 계산 (Yes/No 비율)
- 일관성 계산
- GT 질문 확인 및 업데이트

**실행 결과**:
- 현재 생성된 질문의 상태가 확인됩니다.
- 필요한 경우 GT 질문이 업데이트됩니다.

### 5. 현재 생성된 질문 JSON 저장 (셀 5)

**목적**: 생성된 질문을 JSON 파일로 저장합니다.

**주요 기능**:
- 질문 데이터를 JSON 구조로 변환
- 타임스탬프 기반 파일명 생성
- 메타데이터 추가 (생성 모드, 난이도 범위 등)
- JSON 파일 저장

**실행 결과**:
- `generated_questions_[TYPE]_[TIMESTAMP].json` 파일이 생성됩니다.
- 저장 정보가 전역 변수에 기록됩니다.

### 6. 메모리 상태 점검 (선택적 셀)

**목적**: 메모리 상태를 점검하고 올바른 질문을 설정합니다.

**주요 기능**:
- 전역 변수 상태 확인
- 최근 생성된 질문 확인
- GT 질문 강제 업데이트 (필요한 경우)

**실행 결과**:
- 메모리 상태가 점검됩니다.
- 올바른 질문이 설정됩니다.

### 7. RAG 시스템 테스트 (셀 7-1)

**목적**: Standard RAG와 Boost RAG를 비교 테스트합니다.

**주요 기능**:
- RAG 시스템 초기화
- GT 질문 및 생성된 질문으로 테스트
- Standard RAG와 Boost RAG 실행
- 결과 비교 및 저장

**실행 결과**:
- RAG 테스트 결과가 전역 변수에 저장됩니다.
- 결과 요약이 출력됩니다.

### 8. 개선 효과 분석 (셀 7-2)

**목적**: RAG 시스템의 개선 효과를 분석합니다.

**주요 기능**:
- DataFrame 생성 및 분석
- 상위 질문 상세 분석
- 전체 통계 요약
- 패턴 분석

**실행 결과**:
- 분석 결과가 출력됩니다.
- 차트가 생성되어 저장됩니다.

### 9. 결과 시각화 (셀 8)

**목적**: 실험 결과를 시각화합니다.

**주요 기능**:
- 분포 비교 히스토그램
- 개선량 분포 시각화
- 박스 플롯
- 산점도 생성
- 통계 분석

**실행 결과**:
- 시각화 차트가 생성되어 저장됩니다.
- 통계 분석 결과가 출력됩니다.

### 10. 결과 분석 및 리포트 (셀 9)

**목적**: 종합적인 결과 분석 및 리포트를 생성합니다.

**주요 기능**:
- 모든 실험 결과 종합 분석
- 주요 발견사항 도출
- 권고사항 생성
- 리포트 생성 및 저장

**실행 결과**:
- `b_rag_analysis_report_[TIMESTAMP].md` 파일이 생성됩니다.
- 주요 결과 요약이 출력됩니다.

### 11. 추가 실험 및 커스터마이징 (셀 10)

**목적**: 세션을 마무리하고 추가 실험을 제안합니다.

**주요 기능**:
- 세션 전체 요약
- 추가 실험 제안
- 커스터마이징 가이드 제공
- 세션 정리

**실행 결과**:
- `final_session_summary.json` 파일이 생성됩니다.
- 다음 단계 안내가 출력됩니다.

## 📊 실험 결과 저장 방식

1. **자동 로깅 시스템**:
   - 모든 셀 실행 결과는 `b_rag_experiment_logs/[TIMESTAMP]_session/` 디렉토리에 저장됩니다.
   - 각 셀의 결과는 MD와 JSON 형태로 저장됩니다.
   - 파일명 형식: `cell_[NUMBER]_[NAME]_[TIMESTAMP].[md/json]`

2. **질문 저장**:
   - 생성된 질문은 `generated_questions_[TYPE]_[TIMESTAMP].json` 파일로 저장됩니다.
   - 메타데이터와 함께 모든 질문 정보가 포함됩니다.

3. **시각화 저장**:
   - 생성된 차트는 `[CHART_TYPE]_[TIMESTAMP].png` 형식으로 저장됩니다.
   - 로그 디렉토리에 함께 저장됩니다.

4. **분석 리포트**:
   - 종합 분석 리포트는 `b_rag_analysis_report_[TIMESTAMP].md` 파일로 저장됩니다.
   - 주요 결과, 발견사항, 권고사항이 포함됩니다.

5. **세션 요약**:
   - 최종 세션 요약은 `final_session_summary.json` 파일로 저장됩니다.
   - 실험 정보, 추가 실험 제안, 다음 단계가 포함됩니다.
